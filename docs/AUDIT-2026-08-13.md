# Audit of 2026-08-13 — findings and resolutions

An adversarially verified bug and dead-code audit was run against commit
`8493313` (the Phase 5 UI rework). Method: eight parallel finders
(concurrency, UI interaction, screen state, engine timing, importers,
error handling, dead symbols, duplication) seeded by a static-tooling
pass and a symbol reference map; every finding was then attacked by two
independent verifiers with opposing lenses — one trying to construct the
failure, one hunting for an existing guard, both instructed to refute
when uncertain — and only findings neither could knock down were kept. A
completeness critic then hunted for what the finders missed. 58 raised,
7 refuted, 4 contested, 46 confirmed; 32 unique after dedupe.

This document is the permanent record: every finding, its root cause,
and how it was resolved. IDs group by origin: **A** = regressions
introduced by `8493313`, **B** = malformed files could kill or wedge the
process, **C** = device/config coherence, **D** = correctness and
honesty, **E** = contested findings that needed investigation before a
verdict.

Fix commits: `a202258` (A + C series, D1, D4), `5fcc8b8` (importer
hardening), `edfd6e7` (engine/practice/live/audiofile), plus the
verification follow-up commit carrying this document.

## B — malformed files could kill or wedge the process (all fixed; pre-existing)

These matter because the importers parse untrusted files and the README
actively solicits real-world Guitar Pro / MusicXML exports.

| ID | Where | Finding | Resolution |
|----|-------|---------|------------|
| B1 | `internal/midiimport` `barSpecs` | A ~50-byte MIDI with `division=1` and a delta of `0xFFFFFFFF` scaled to ~4.1e12 ticks ≈ 1.07e9 bars → unrecoverable OOM abort. | `MaxTicks` (100M) and `maxBars` (100k) caps, mirroring the ones `mxlimport` already had; a file over them errors with "score too long". Tests: `TestImportHostileExtentCapped`, `TestImportTinyBarsCapped`. |
| B2 | `internal/midiimport` `readMaps` + `score.Validate` | A time-signature denominator byte ≥ 8 decodes to `Den == 0` (uint8 overflow in the MIDI library); placed after the last note it escaped the only check, loaded, validated — then dividing by `Den` panicked when the user sought to the end (the new timeline made this one click). | Invalid meters are skipped with a warning at import, and `score.Validate` now rejects `Num < 1`, `Den < 1`, `Den > 4·PPQ` as defense in depth. Tests: `TestImportZeroDenMeterSkipped`, `TestImportZeroNumMeterSkipped`, Validate bound cases. |
| B3 | `internal/audiofile` `resampleLinear` | A 167 KB WAV declaring `sampleRate=1` made two ~8 GB allocations → OOM abort. FLAC's STREAMINFO could do the same; MP3 is table-bound and could not. | Declared rates outside 1,000–768,000 Hz are rejected in `Load`, one policy check covering all decode paths and capping resample amplification at 48×. Test: `TestImplausibleSampleRateRejected`. |
| B4 | `internal/mxlimport` + `internal/fretting` | A 10 KB MusicXML declaring a 40-line tab staff plus one 15-note chord drove `fretting`'s injective search to P(40,15) ≈ 5e22 nodes (~11 years) — the app wedged forever. | Two layers: tab staves above 25 lines are rejected with a warning (standard tuning kept), and `fretting.Assign` carries a per-beat search budget (100k nodes / 512 candidates) that falls back to the existing greedy assignment. `gpimport`'s unbounded `Pitches` tuning got the same 25 cap. Tests include the actual attack file completing in under a second. |
| B5 | `internal/gpimport` `layoutBars` | A time-signature numerator that is a multiple of 2^56 wrapped the bar length to exactly zero; the all-zero-length score passed Validate and imported "successfully". | Numerator/denominator bounded at 256; the file errors. Test: `TestImportHugeTimeSignatureRejected`. |
| B6 | `internal/gpimport` `beatNotes` / `trackSetup` | One out-of-range fret (or capo) pushed a pitch past MIDI 127 and the final Validate discarded the entire otherwise-good import — against the package's own contract. | Out-of-range frets drop with a warning naming them; capo clamps with a warning; a still-impossible pitch drops rather than failing the import. Test: `TestImportOutOfRangeFretDropped`. |

## C — device and config coherence (all fixed; pre-existing)

| ID | Where | Finding | Resolution |
|----|-------|---------|------------|
| C1 | `cmd/guitartutor/live.go` `setupListen` | The live session re-loaded `config.json` from disk while everything else read the in-memory prefs — after a failed save the stream silently opened on the wrong device with offset 0 while settings showed the calibration as measured. | `setupListen` takes the caller's config as a parameter: the shell passes its in-memory prefs snapshot, the CLI loads the file explicitly. |
| C2 | `cmd/guitartutor/shell.go` vs `internal/ui/settings.go` | Two different "same physical interface?" heuristics shipped in one binary and disagreed on ordinary Windows names — settings warned where the practice view stayed silent. | One implementation: `ui.SameAudioInterface` is exported and the shell's first-word variant is deleted. |
| C3 | `internal/ui/settings.go` `resolveDevice` vs `cmd` `fillDeviceID` | Settings silently showed a default fallback as selected when the saved device was unplugged, while the open path handed the stale ID straight to the backend — the display and the stream disagreed. | `fillDeviceID` falls back to the concrete default *with a note the caller surfaces* (stderr, and the live-warning banner); the settings screen says when its shown selection is a fallback. Tests: `TestFillDeviceIDStaleRemembered`. |
| C4 | `cmd/guitartutor/shell.go` `warnOnSplitDevices` | An unset playback ID was converted to the literal display string "system default" before comparison — a name matching no real interface, raising a permanent unfounded split-device banner. | `resolvedDeviceName` resolves what an ID will actually be used as (the default device's real name), and unknown never warns. Test: `TestResolvedDeviceName`. |
| C5 | `cmd/guitartutor/main.go` `runPlay` | `play -countin N` drew the COUNT-IN toggle as off while the engine counted in; pressing C to "turn it on" turned it off. | `runPlay` syncs the view's mirror with `SetCountIn`. |

## D — correctness and honesty (all fixed; pre-existing)

| ID | Where | Finding | Resolution |
|----|-------|---------|------------|
| D1 | `cmd/guitartutor/main.go` `runRender` | The success line printed and the process exited 0 before the deferred `Close` — whose error, a failed final flush, was discarded. A truncated WAV shipped with a success message. | `Close` is checked before success is claimed. |
| D2 | `internal/engine/render.go` wait halt | While halted at a wait point the published position was reconstructed from the floored action frame: `PosTick()` reported `waitTick−1` whenever frames-per-tick was fractional, so the UI showed the bar *before* the note being waited on. | The halted position is the wait tick itself — a sub-frame, forward-only relabeling; resume arithmetic is frame-based and untouched. | D3 | `internal/practice` `WaitConfirmed` | Wait pre-matches were keyed Track+Key+Start, so a guitar unison (two strings, same pitch, same tick) collapsed to one entry and the second note aged into a false Miss — the project's named number-one rage-quit cause. | The key includes the string; one detection credits both unison notes, per the forgiving-scoring principle. Tests: `TestScorerWaitConfirmedUnison`, `…ConsumedExactly`. |
| D4 | `cmd/guitartutor/shell.go` | Q is labelled "Quit guitarTutor" in the footer and the help overlay, but nothing wired `SetQuitAll` — under the shell Q behaved exactly as Escape, and two adjacent help rows promised different things while doing the same one. | `Shell.Quit` exists (dropping every screen with proper teardown) and the shell wires Q to it. | D5 | `internal/live` `analyzer.drain` | A ring-overflow gap noticed one iteration late was stamped at a write cursor that had already advanced past the loss, splicing the zeroed gap *after* capture that came after it. | The producer publishes the loss position (`dropAt`, stored at the instant of overflow, position-before-count) and the consumer uses it; a defensive clamp covers the theoretical late-notice corner. ## E — contested findings, investigated to a verdict

| ID | Where | Claim | Verdict and resolution |
|----|-------|-------|------------------------|
| E1 | `internal/engine` `buildSegment` | Looping goes inert when the position sits at or past loop end B. | **Confirmed and fixed for `pos == B`** — reachable three ways through shipped UI (timeline scrub to B, dragging the B edge onto a beat-parked playhead, pressing B after playback ran out). The loop boundary now engages at `pos == B` and wraps to A; the degenerate wrap does not count a pass or feed the tempo ramp. `pos > B` deliberately stays dormant (DAW convention), now documented and pinned by test. Tests: `TestSeekToLoopEndWrapsIn`, `TestPlayAtScoreEndWithLoopAtEnd`, `TestLoopBehindPlayheadStaysDormant`, `TestSeekToLoopEndDoesNotRamp`. |
| E2 | `internal/midiimport` `buildTrack` | O(bars × segments × notes) import. | **Confirmed empirically** — 24 s to import a 200k-note file, 91.5% of CPU in the two full-list scans; the B1 caps bound bars but not notes, so a small hostile file still bought minutes of CPU. Rewritten to an edge-bucketing pass plus an advancing-cursor sweep (effectively linear), output byte-identical under the existing exact-output tests. The same quadratic in `mxlimport`'s `buildTrack` got the same fix. |
| E3 | `internal/fretting` `enumerate` | The taken-strings bitmask is a `uint32`; at ≥ 32 strings chord notes double up on one string. | **Confirmed** (reachable via B4's 40-line staff before its cap landed). Mask widened to `uint64`, strings past 63 yield no position by construction, and the B4 caps make ≥ 32 strings unreachable from any importer — belt and suspenders. Test: 33-string unison assigns distinct strings. |
| E4 | `internal/ui` `trackMarks` | Dead or merely test-covered. | Dead in production; deleted with its tests rewritten against `trackStateText` (see A11). |

## Verification of the fixes

The three fix commits were themselves verified the same way the audit
ran: one skeptic per finding attempted to reconstruct the original
failure against the fixed code (all 32 verified fixed), and nine
reviewers (three commits × correctness / behavioural-equivalence /
concurrency lenses) hunted the diffs for regressions the fixes
introduced, with every candidate adversarially refuted before being
believed.

Five regressions survived refutation (one reported through two lenses)
and were fixed with their own regression tests:

| Where | Regression | Resolution |
|-------|-----------|------------|
| `internal/ui/settings.go` | The C3 "saved device is not connected" note was computed once at screen construction, so it kept showing after the user explicitly selected a connected device — when both of its claims were false. | `refreshMissing` recomputes on every device commit. Test: `TestSettingsFallbackNoteClearsOnSelection`. |
| `internal/ui/ui.go` | The A6 wiring latched `settingsTouched` on every unapplied C press with nothing clearing it: toggling the count-in and back left a permanent false "press F5" prompt. | Pending is now a comparison against the count-in the engine was built with, not a latch; a round trip withdraws the offer, and the settings screen's own (round-trip-guarded) flag is untouched. Test: `TestCountInRoundTripWithdrawsThePrompt`. |
| `internal/ui/shell.go` | `Shell.Quit` could be silently undone by a `Show` queued later in the same frame (pending edits run in order), leaving the app running with its screens gone and the piece's audio orphaned. | Quit sets a terminal `quitting` flag; `Show`/`Replace` become no-ops after it and `Update` exits regardless. Test: `TestQuitBeatsSameFrameStackEdits`. |
| `internal/fretting/fretting.go` | The B4 node budget, with the span rule checked only at leaves, exhausted inside doomed low-fret subtrees: a playable 8-note chord on a real 14-string tuning — inside the import cap, fingered in milliseconds by the pre-budget code — came back with a note falsely dropped as "no free string in chord". | The span rule is enforced inside the recursion (admissible: a partial fingering's span only grows), so legitimate wide-tuning chords finger jointly again while the budget still bounds hostile input. Test: `TestAssignWideTuningJointFingering`. |
| `internal/engine` / `internal/ui` | The E1 loop-engagement change made a next-bar step onto the loop end warp to the loop start — but only once rendering resumed, so the paused and playing cases behaved differently and the wrap read as a warp nobody asked for. | Resolved as deliberate loop-aware navigation: `seekNextBar` inside an armed loop wraps to the loop start explicitly and immediately in both transport states; backward navigation still exits (a rewind re-enters the loop naturally), and leaving forward is L or a timeline click past the end. Documented in the help overlay. Test: `TestNextBarInsideLoopWraps`. |

## Explicitly not fixed

- **Genuinely huge legitimate inputs** still cost proportional memory
  (a multi-GB backing track is large-in, large-out); the fixes remove
  *amplification*, not honest size.
- The audit's refuted findings (7) and the survey's flagged-but-guarded
  symbols (optional interfaces, build-tag paths, test seams) are not
  listed here; the point of the adversarial pass was to keep them out.
